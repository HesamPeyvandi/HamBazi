# راهنمای کامل استقرار: GitHub ← Neon ← Vercel

هدف: نسخهٔ **دمو** هم‌بازی روی اینترنت بالا بیاید (ورود با OTP نمایشی، پرداخت شبیه‌سازی‌شده، عکس‌ها روی Vercel Blob).
این راهنما برای کسی نوشته شده که قبلاً این سرویس‌ها را استفاده نکرده است. دستورها برای **ویندوز (PowerShell)** و مک/لینوکس هر دو آمده‌اند.

> **مهم:** این استقرار «دمو» است (`APP_ENV=demo`). هر کسی می‌تواند با هر شماره‌ای وارد شود چون کد OTP روی صفحه نشان داده می‌شود، و هیچ پولی جابه‌جا نمی‌شود. این نسخه را به‌عنوان محصول واقعی منتشر نکنید. نسخهٔ واقعی (SMS واقعی، درگاه پرداخت) در فازهای بعد است و سرور production اجازهٔ اجرای این تنظیمات دمو را **نمی‌دهد**.

## ۰) پیش‌نیازها و تصویر کلی

| لازم دارید | توضیح |
|---|---|
| Node.js نسخهٔ ۲۲ | از nodejs.org؛ با `node -v` بررسی کنید |
| Git | از git-scm.com؛ با `git --version` بررسی کنید |
| حساب GitHub | رایگان |
| حساب Neon | رایگان (neon.tech) |
| حساب Vercel | رایگان (Hobby)؛ ورود با GitHub ساده‌ترین راه است |

جریان کار: کد ← GitHub ← (هر push) ← Vercel خودکار build می‌کند ← به Neon (PostgreSQL) وصل می‌شود ← عکس‌ها در Vercel Blob.

```
کامپیوتر شما ──git push──▶ GitHub ──webhook──▶ Vercel (Next.js)
                                                  │        │
                                              Neon (DB)   Blob (عکس)
```

وضعیت دسترسی از ایران: شما تأیید کردید که Vercel از ایران باز می‌شود. دسترسی به **داشبورد Neon و GitHub** را من نمی‌توانم از اینجا آزمایش کنم؛ اگر یکی از آن‌ها بدون VPN باز نشد، فقط برای مدیریت (ساخت حساب/دیتابیس) از VPN استفاده کنید — برنامهٔ در حال اجرا روی Vercel به Neon از سرور وصل می‌شود و به شبکهٔ شما ربطی ندارد.

## ۱) آماده‌سازی پروژه روی کامپیوتر

۱. فایل `hambazi-phase2.zip` را در یک پوشه Extract کنید (مثلاً `C:\Projects\hambazi`).
۲. ترمینال را در همان پوشه باز کنید (در ویندوز: روی پوشه راست‌کلیک ← «Open in Terminal»).
۳. وابستگی‌ها را نصب کنید:
```bash
npm install
```
۴. بررسی کنید که پروژه build می‌شود (اختیاری ولی توصیه می‌شود). یک فایل `.env` از روی نمونه بسازید:
```bash
# مک/لینوکس
cp .env.example .env
# ویندوز PowerShell
Copy-Item .env.example .env
```
(برای build محلی لازم نیست دیتابیس واقعی باشد؛ اما `npm run build` به مقادیر env نیاز دارد. فعلاً همین نمونه کافی است.)

## ۲) GitHub

### ۲.۱ ساخت مخزن (Repository)
۱. وارد github.com شوید ← دکمهٔ **New repository** (علامت + بالای صفحه).
۲. **Repository name:** `hambazi`
۳. **Private** را انتخاب کنید (مهم: کد شما عمومی نشود).
۴. تیک «Add a README / .gitignore / license» را **نزنید** (پروژه خودش دارد).
۵. **Create repository**. صفحهٔ بعد آدرس مخزن را نشان می‌دهد، مثل `https://github.com/<نام-کاربری>/hambazi.git`.

### ۲.۲ اطمینان از اینکه رمزها آپلود نمی‌شوند
فایل `.gitignore` پروژه از قبل `.env`، `node_modules`، `.next` و `.uploads` را نادیده می‌گیرد. بعد از commit این را چک می‌کنیم (مرحلهٔ ۲.۴).

### ۲.۳ معرفی خودتان به Git (فقط بار اول)
```bash
git config --global user.name "نام شما"
git config --global user.email "ایمیل-حساب-گیتهاب"
```

### ۲.۴ commit و push
```bash
git init
git branch -M main
git add .
git commit -m "HamBazi phase 2"
```
**قبل از push** مطمئن شوید `.env` وارد نشده:
```bash
git ls-files | findstr /i "\.env"     # ویندوز CMD/PowerShell
git ls-files | grep "\.env"            # مک/لینوکس
```
فقط باید `.env.example` را ببینید. اگر `.env` نشان داده شد: `git rm --cached .env` و دوباره commit کنید.

حالا اتصال و ارسال:
```bash
git remote add origin https://github.com/<نام-کاربری>/hambazi.git
git push -u origin main
```
GitHub برای رمز، **رمز حساب را قبول نمی‌کند**. دو راه ساده:
- **راه الف (پیشنهادی):** نصب GitHub CLI (cli.github.com) و اجرای `gh auth login` (گزینهٔ HTTPS و مرورگر)، سپس دوباره `git push`.
- **راه ب:** GitHub ← Settings ← Developer settings ← Personal access tokens ← **Tokens (classic)** ← Generate ← تیک `repo` ← توکن را جای رمز در ترمینال بچسبانید.

پس از push، صفحهٔ مخزن را رفرش کنید؛ باید فایل‌ها را ببینید.

## ۳) Neon (دیتابیس PostgreSQL)

### ۳.۱ ساخت پروژه
۱. console.neon.tech ← ثبت‌نام (می‌توانید با GitHub).
۲. **Create project** (یا New project):
   - **Name:** `hambazi`
   - **Postgres version:** ۱۶ یا بالاتر (پروژه با ۱۶ آزمایش شده)
   - **Region:** نزدیک‌ترین ناحیهٔ اروپا (مثلاً **Frankfurt / eu-central-1**) — این را یادداشت کنید، در مرحلهٔ ۷ لازم می‌شود.
۳. **Create**.

### ۳.۲ گرفتن رشتهٔ اتصال (Connection string)
در داشبورد پروژه دکمهٔ **Connect** را بزنید. دو نوع آدرس لازم است (سوییچ **Connection pooling**):

| نوع | چه زمانی | شکل |
|---|---|---|
| **Pooled** (تیک Connection pooling روشن) | برای **Vercel** (برنامهٔ در حال اجرا) | `postgresql://user:pass@ep-xxxx-pooler.region.aws.neon.tech/neondb?sslmode=require` |
| **Direct** (تیک خاموش) | برای **مهاجرت و seed** از کامپیوتر شما | `postgresql://user:pass@ep-xxxx.region.aws.neon.tech/neondb?sslmode=require` |

هر دو را در یک فایل متنی موقت نگه دارید (**جایی منتشرشان نکنید و در چت نفرستید**؛ این‌ها رمز دیتابیس‌اند).
کد پروژه برای PgBouncer (آدرس pooled) آماده است (`prepare:false`).

افزونهٔ `btree_gist` که برای جلوگیری از هم‌پوشانی سانس لازم است توسط Neon پشتیبانی می‌شود و مهاجرت پروژه خودش آن را فعال می‌کند.

## ۴) مهاجرت و دادهٔ نمونه

این دو دستور از **کامپیوتر شما** روی دیتابیس Neon اجرا می‌شوند. از آدرس **Direct** استفاده کنید.

**ویندوز PowerShell:**
```powershell
$env:DATABASE_URL = "postgresql://...آدرس-direct..."
npm run db:migrate
$env:APP_ENV = "demo"
npm run db:seed
```
**مک/لینوکس:**
```bash
export DATABASE_URL="postgresql://...آدرس-direct..."
npm run db:migrate
APP_ENV=demo npm run db:seed
```
انتظار می‌رود ببینید: `migrations applied` و بعد `seeded: 8 venues, 9 users`.

⚠️ `db:seed` **همهٔ داده‌های دیتابیس را پاک می‌کند** و داده نمونه می‌سازد. فقط روی دیتابیس دمو بزنید، هرگز روی دیتابیسی که اطلاعات مهم دارد. اگر `APP_ENV=production` یا خالی باشد خودش اجرا نمی‌شود.

داده‌های نمونه: ۸ سالن فرضی در سمنان با سانس‌های ۱۰ روز آینده و ۹ کاربر (بازیکن ۰۹۰۰۰۰۰۰۰۰۱، مدیر سالن ۰۹۰۰۰۰۰۰۰۰۲، ادمین ۰۹۰۰۰۰۰۰۰۰۳). سانس‌های seed بعد از ۱۰ روز تمام می‌شوند: یا دوباره seed بزنید یا مالک سالن از پنل خودش سانس جدید بسازد.

اگر خواستید مطمئن شوید: در Neon ← **Tables** باید جدول‌هایی مثل `venues`، `reservations`، `payment_intents` را ببینید.

## ۵) Vercel

### ۵.۱ ساخت پروژه
۱. vercel.com ← **Sign Up / Log in** ← **Continue with GitHub**.
۲. **Add New… ← Project**.
۳. اگر مخزن `hambazi` را نمی‌بینید: **Adjust GitHub App Permissions** ← به Vercel دسترسی به همین مخزن را بدهید.
۴. کنار `hambazi` دکمهٔ **Import**.
۵. تنظیمات: **Framework Preset = Next.js** (خودکار)، Root Directory همان پیش‌فرض، Build/Output را دست نزنید. (Node.js Version در Settings ← General روی ۲۲.x باشد.)

### ۵.۲ متغیرهای محیطی (قبل از Deploy)
بخش **Environment Variables** همان صفحه را باز کنید و این‌ها را اضافه کنید (برای همهٔ محیط‌ها Production/Preview/Development تیک بزنید):

| نام | مقدار | توضیح |
|---|---|---|
| `APP_ENV` | `demo` | حالت دمو |
| `DATABASE_URL` | آدرس **Pooled** نئون | از مرحلهٔ ۳.۲ |
| `OTP_HMAC_SECRET` | رشتهٔ تصادفی ≥۳۲ نویسه | پایین‌تر چطور بسازید |
| `SESSION_SECRET` | رشتهٔ تصادفی دیگر ≥۳۲ نویسه | با قبلی فرق داشته باشد |
| `CRON_SECRET` | رشتهٔ تصادفی | Vercel Cron با همین مقدار احراز هویت می‌کند |
| `APP_URL` | فعلاً `https://hambazi.vercel.app` (بعداً اصلاح می‌شود) | آدرس نهایی سایت؛ در لینک‌های دعوت استفاده می‌شود |
| `SMS_PROVIDER` | `mock` | فقط دمو |
| `PAYMENT_MODE` | `simulated` | فقط دمو |
| `BLOB_READ_WRITE_TOKEN` | خودکار (مرحلهٔ ۶) | |

ساخت رشتهٔ تصادفی (هر بار یک مقدار جدید):
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

### ۵.۳ Deploy
دکمهٔ **Deploy**. ۲ تا ۳ دقیقه صبر کنید. در صورت موفقیت آدرس `https://<نام>.vercel.app` ساخته می‌شود.

### ۵.۴ اصلاح `APP_URL`
آدرس واقعی را از داشبورد کپی کنید ← Settings ← Environment Variables ← `APP_URL` را به همان مقدار تغییر دهید ← **Deployments** ← سه‌نقطهٔ آخرین deploy ← **Redeploy**.

### ۵.۵ Cron (جاروب انقضا)
فایل `vercel.json` موجود است و روزی یک‌بار `/api/cron/sweep` را صدا می‌زند (حداکثر مجاز در پلن رایگان). **درستی سیستم به cron وابسته نیست**: انقضای هولد و مهلت سانس‌ها در هر خواندن/نوشتن هم به‌صورت تراکنشی بررسی می‌شود؛ cron فقط پشتیبان است. در Vercel ← Settings ← Cron Jobs باید یک job ببینید.

### ۵.۶ دامنه (بعداً)
Settings ← Domains ← Add. فعلاً دامنه ندارید و لازم نیست؛ بعد از خرید، رکوردهایی که Vercel نشان می‌دهد را در DNS دامنه بگذارید، سپس `APP_URL` را عوض کنید.

## ۶) Vercel Blob (آپلود عکس)

۱. در Vercel، پروژهٔ `hambazi` ← تب **Storage** ← **Create Database / Create** ← **Blob**.
۲. نام: `hambazi-images` ← **Access: Public** ← ناحیه‌ای نزدیک (مثلاً Frankfurt) ← Create.
۳. **Connect to Project** را برای `hambazi` بزنید. متغیر `BLOB_READ_WRITE_TOKEN` خودکار اضافه می‌شود.
۴. یک **Redeploy** بزنید تا توکن در برنامه فعال شود.

بدون این مرحله سایت کار می‌کند ولی آپلود عکس پیام «برای آپلود عکس روی Vercel باید BLOB_READ_WRITE_TOKEN تنظیم شود» می‌دهد.
محدودیت: بدنهٔ درخواست در Vercel حدود ۴٫۵ مگابایت است؛ پروژه حداکثر **۴ مگابایت** برای هر عکس قبول می‌کند (عکس سپس به WebP حداکثر ۱۶۰۰ پیکسل تبدیل می‌شود).

## ۸) تست بعد از استقرار (چک‌لیست)

آدرس سایت را باز کنید:
- [ ] صفحهٔ اصلی و فهرست سالن‌ها باز می‌شود، ارقام فارسی و راست‌به‌چپ است.
- [ ] نوار بالای صفحه «محیط دمو…» را نشان می‌دهد.
- [ ] ورود با `۰۹۰۰۰۰۰۰۰۰۱` ← کد روی صفحه نمایش داده می‌شود ← وارد می‌شوید.
- [ ] یک سالن ← یک سانس ← «رزرو و ادامه به پرداخت» ← صفحهٔ پرداخت با هشدار زرد و شمارندهٔ ۱۵ دقیقه ← «پرداخت (شبیه‌سازی)» ← رزرو تأیید می‌شود.
- [ ] «رزروهای من» ← رزرو دیده می‌شود ← «لغو» ← بازگشت وجه شبیه‌سازی‌شده با درصد درست.
- [ ] یک سانس باز بسازید و با کاربر دوم (مرورگر دیگر/حالت ناشناس، شمارهٔ `۰۹۰۰۰۰۰۰۰۱۱`) بپیوندید.
- [ ] با `۰۹۰۰۰۰۰۰۰۰۲` (مالک) ← «پنل مالک» ← سالن جدید ← آپلود عکس ← ارسال برای تأیید؛ با `۰۹۰۰۰۰۰۰۰۰۳` (ادمین) ← «تأیید سالن‌ها»؛ مالک سانس بسازد.
- [ ] زنگ اعلان عدد خوانده‌نشده‌ها را نشان می‌دهد.
- [ ] در Vercel ← **Logs**: خطای قرمز تکراری نباشد.

نتیجه (باز شد/نشد + خطا) را برای من بنویسید؛ من تا شما تأیید نکنید **ادعا نمی‌کنم** که استقرار کار کرده.

## ۱۰) عیب‌یابی

| علامت | علت محتمل | راه‌حل |
|---|---|---|
| Build خطای `Unsafe or incomplete configuration` | env ناقص (مثلاً `OTP_HMAC_SECRET` کوتاه) | مقادیر را بررسی کنید؛ حداقل ۳۲ نویسه |
| سایت ۵۰۰ می‌دهد و در Logs خطای اتصال DB | `DATABASE_URL` غلط یا بدون `sslmode=require` | آدرس Pooled را دوباره کپی کنید |
| `relation "venues" does not exist` | مهاجرت اجرا نشده | مرحلهٔ ۴ را با آدرس Direct انجام دهید |
| `type "..." does not exist` / `btree_gist` | مهاجرت نیمه‌کاره | `npm run db:migrate` را دوباره اجرا کنید |
| ورود OTP کد نمی‌دهد | `SMS_PROVIDER` برابر `mock` نیست | `mock` بگذارید (فقط دمو) |
| «پرداخت آنلاین هنوز فعال نیست» | `PAYMENT_MODE` برابر `simulated` نیست | تنظیم و Redeploy |
| آپلود عکس خطا | توکن Blob نیست / عکس > ۴ مگابایت | مرحلهٔ ۶؛ عکس را کوچک کنید |
| عکس آپلودشده نمایش داده نمی‌شود | CSP یا Blob خصوصی ساخته شده | Blob باید **Public** باشد |
| سایت کند است | ناحیهٔ Vercel و Neon متفاوت | مرحلهٔ ۷ |
| لینک دعوت `localhost` یا آدرس غلط | `APP_URL` غلط | مرحلهٔ ۵.۴ |
| `git push` رد می‌شود (authentication failed) | رمز حساب استفاده شده | مرحلهٔ ۲.۴ (توکن یا `gh auth login`) |
| Cron اجرا نمی‌شود | پلن رایگان فقط روزی یک‌بار | طبیعی است؛ منطق اصلی به cron وابسته نیست |
| دسترسی به یکی از سرویس‌ها از ایران ممکن نیست | محدودیت شبکه | فقط برای مدیریت از VPN استفاده کنید؛ بگویید تا گزینهٔ جایگزین بررسی کنیم |

- Vercel Hobby، Neon Free و Vercel Blob طرح رایگان دارند؛ **سقف‌ها و شرایط را همیشه از صفحهٔ قیمت‌گذاری خودشان ببینید** (من نمی‌توانم از اینجا مقدار فعلی را تضمین کنم).
- **Vercel Hobby طبق شرایط خودش برای استفادهٔ غیرتجاری است.** برای دمو/آزمایش مشکلی نیست؛ برای کسب‌وکار واقعی باید پلن Pro (یا میزبان دیگر) انتخاب شود — تصمیم این موضوع در فاز ۹ است.
- Neon رایگان بعد از مدتی بی‌کاری دیتابیس را «خواب» می‌برد؛ اولین درخواست بعد از خواب چند ثانیه کندتر است.

## ۱۲) برای نسخهٔ واقعی بعداً عوض می‌شود
`APP_ENV=production`، `SMS_PROVIDER` واقعی (کاوه‌نگار/ملی‌پیامک) با کلید API، درگاه پرداخت واقعی، دامنهٔ اختصاصی، پلن مناسب تجاری، متن‌های حقوقی بازبینی‌شده، بررسی قانونی نگهداری وجه، پشتیبان‌گیری از دیتابیس. این‌ها در فازهای ۷ تا ۹ برنامه‌ریزی شده‌اند و تا آن زمان سرور production با تنظیمات دمو بالا نمی‌آید.
