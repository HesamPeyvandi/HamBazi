# فاز ۱۲-۳ — رفع پیام «برای این روز سانس خالی ثبت نشده است»

## علت
اسکریپت seed برای ۱۰ روز آینده (از زمان seed) سانس می‌سازد. پس از گذشت ۱۰ روز، همهٔ سانس‌های دمو در گذشته‌اند و صفحهٔ سالن برای تمام روزها این پیام را نشان می‌دهد. این موضوع به تغییرات فاز ۱۲-۲ مربوط نیست (کوئری `slotsForDay` و صفحه دست‌نخورده‌اند) و نیازی به برگشت نبود.

## راه‌حل
- `src/db/demo-slots.ts` — `extendDemoSlots(days)`: برای سالن‌های منتشرشده سانس‌های ۱۶:۰۰ تا ۲۲:۰۰ را با قیمت و طول هر سالن اضافه می‌کند. `onConflictDoNothing` روی ایندکس یکتا؛ هیچ‌چیز حذف یا تغییر نمی‌کند.
- `npm run db:slots [days]` — اجرای دستی.
- `DEMO_AUTO_SLOTS=1` — اجرای خودکار در build ورسل و کرون روزانهٔ `/api/cron/sweep` (فقط وقتی `APP_ENV` برابر production نیست).
- سالن‌های واقعی: مالک سالن سانس را در پنل خودش می‌سازد؛ این مکانیزم در production اجرا نمی‌شود.

## تأیید
`select max(starts_at) from time_slots;` باید تاریخی در ۱۴ روز آینده باشد.

## پرسش‌های تکمیلی

**چرا بعد از دیپلوی اتفاقی نیفتاد؟** build ورسل فقط وقتی `VERCEL_ENV=production` باشد به دیتابیس دست می‌زند (مهاجرت و seed هم همین‌طورند). اگر `DEMO_AUTO_SLOTS` فقط برای Preview/Development تنظیم شده باشد، build آن را نمی‌بیند. راه‌حل: متغیر را برای **Production** هم بگذارید (با `APP_ENV=demo`) و دوباره دیپلوی کنید. لاگ build یکی از این خط‌ها را می‌نویسد: «adding the missing demo slots» یا دلیل رد شدن.

**دستی یا خودکار؟** با `DEMO_AUTO_SLOTS=1` کاملاً خودکار است: هر build و هر روز ساعت ۳ بامداد (کرون `/api/cron/sweep`) سانس‌های ۱۴ روز آینده تکمیل می‌شود؛ هیچ اقدام دستی لازم نیست. کرون نیازی به build ندارد و فقط `CRON_SECRET` درست لازم دارد.

## رزرو دائمی (هفتگی)
- مسیر: پنل مالک ← سالن ← «رزروهای دائمی» (دکمه در صفحهٔ سالن و صفحهٔ سانس‌ها).
- فیلدها: نام مجموعه، روز هفته (شمسی)، ساعت شروع/پایان (گام ۳۰ دقیقه)، تاریخ شروع و پایان (شمسی)، یادداشت اختیاری. حداکثر ۴۰۰ روز.
- اثر: سانس‌های باز آن بازه (همهٔ ورزش‌های سالن) `closed` می‌شوند و `block_id` می‌گیرند؛ صفحهٔ عمومی آن‌ها را «رزرو شده» (بدون لینک) نشان می‌دهد و `/book/[id]` می‌گوید قابل رزرو نیست. مالک نمی‌تواند چنین سانسی را دستی باز کند؛ باید رزرو دائمی را ویرایش/لغو کند.
- سانس‌های ساخته‌شده بعدی (پنل مالک، `db:slots`) خودکار بسته می‌شوند (`applyBlocks`).
- ویرایش: سانس‌های قبلی آزاد و بازهٔ جدید اعمال می‌شود (اتمیک). لغو: سانس‌ها باز می‌شوند، ردیف با وضعیت «لغو شده» می‌ماند.
- ایمنی: اگر در بازه سانس `booked/held` باشد ثبت/ویرایش رد می‌شود؛ همپوشانی دو رزرو دائمی رد می‌شود؛ فقط مدیران همان سالن (و ادمین) دسترسی دارند؛ همه‌چیز در audit log ثبت می‌شود.
- فایل‌ها: `src/db/blocks-sql.ts`، `src/server/owner/blocks.ts`، `src/app/owner/venues/[id]/blocks/page.tsx`، migration `0011_recurring_blocks.sql`.
