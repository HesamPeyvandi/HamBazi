# تحویل فاز ۸ — PWA، آفلاین، دسترس‌پذیری + اصلاحات چت و ورود مالک

## ۱. چه چیزی ساخته شد
| بخش | خلاصه |
|---|---|
| اصلاحات چت | خطای hydration (فرم داخل `<p>`) رفع شد. زیر پیام فقط «پاسخ» می‌ماند. «پاسخ / گزارش پیام / مسدود کردن» در منوی راست‌کلیک (دسکتاپ) یا تپ روی پیام (دستگاه لمسی) است؛ Escape یا کلیک بیرون آن را می‌بندد؛ منو با اسکرول خودکار پولینگ بسته نمی‌شود. پیام‌های خودتان سمت راست، دیگران سمت چپ؛ ورودی راست‌چین. منوی پیام خودتان فقط «پاسخ» دارد. |
| ورود مدیر سالن | بعد از ورود، نقش `venue_manager` مستقیم به `/owner` می‌رود. اگر لینک عمیق (`?next=/owner/reservations`) باشد همان باز می‌شود. ادمین و بازیکن مثل قبل. |
| PWA | `manifest.webmanifest` (فارسی، RTL، standalone، میان‌برها)، آیکن‌های `public/icons/*`، دکمهٔ نصب در فوتر (Chrome/Android با prompt؛ iOS راهنمای «Add to Home Screen»؛ در حالت نصب‌شده پنهان). |
| Service Worker | `public/sw.js`: فقط فایل‌های ثابت cache-first؛ ناوبری شبکه‌محور و در صورت قطعی `public/offline.html` (ایستا و بدون اطلاعات شخصی). درخواست‌های غیر GET، API، اکشن‌ها و صفحات هرگز کش نمی‌شوند. فقط در build production ثبت می‌شود. با تغییر `VERSION` کش قدیمی پاک می‌شود. |
| نوار آفلاین | هنگام قطع اینترنت «اتصال اینترنت قطع است…» بالای صفحه. |
| دسترس‌پذیری | axe-core (WCAG 2.0/2.1 A و AA) روی ۱۲ صفحه (خانه، سالن‌ها، صفحهٔ سالن، ورود، سانس‌ها، تیم‌ها، راهنما، قوانین، پروفایل، فهرست چت، علاقه‌مندی‌ها، اعلان‌ها): ۰ تخلف جدی/بحرانی. |

## ۲. مهاجرت و متغیر محیطی
ندارد. وابستگی توسعهٔ جدید: `axe-core` (فقط برای تست؛ `npm install` کافی است).

## ۳. اجرا و تست
```
npm install
npm run build && npm start      # SW فقط در production فعال است
E2E_DB_URL=<url> node tests/e2e/phase8.mjs
```
نتیجهٔ واقعی: Vitest ‏۱۸۸/۱۸۸؛ E2E فازهای ۱ تا ۸: ۷۲، ۶۲، ۴۷، ۶۶، ۳۹، ۲۸، ۳۳، ۲۷ — همه پاس؛ `tsc`/`eslint`/`next build` بدون خطا.
(یک‌بار در اجرای پشت‌سرهم، بررسی «register validates required fields» فاز ۱ رد شد و در دو اجرای بعدی پاس شد؛ به‌نظر زمان‌بندی تست است، نه رفتار برنامه.)

## ۴. محدودیت‌ها و آنچه تست نشده
- منوی تپ روی موبایل با شبیه‌ساز لمسی Chromium تست شده، نه گوشی واقعی؛ نصب واقعی PWA روی Android/iOS تست نشده (فقط manifest، آیکن‌ها، SW و رویداد نصب در Chromium).
- حالت آفلاین فقط صفحهٔ «اتصال برقرار نیست» است؛ رزرو، پرداخت و چت نیاز به اینترنت دارند (عمداً، برای جلوگیری از داده‌های کهنه).
- Push notification اجرا نشده. بررسی دسترس‌پذیری خودکار است (axe)؛ تست با screen reader واقعی انجام نشده.
- فاز ۹ (سخت‌سازی نهایی/انتشار) و ارائه‌دهندهٔ واقعی پیامک باقی مانده است. پرداخت طبق تصمیم شما شبیه‌سازی می‌ماند.

## ۵. چک‌لیست پذیرش
- [ ] در چت، پیام خودتان راست و پیام دیگران چپ است؛ هیچ خطای کنسول نیست.
- [ ] راست‌کلیک (دسکتاپ) / تپ (موبایل) روی پیام دیگران: پاسخ، گزارش، مسدود.
- [ ] ورود با حساب مدیر سالن مستقیم به پنل مالک می‌رود.
- [ ] روی Chrome (production) در فوتر «نصب هم‌بازی روی گوشی» ظاهر می‌شود؛ نصب و باز کردن بدون نوار آدرس.
- [ ] اینترنت را قطع کنید و صفحه‌ای را باز کنید: صفحهٔ «اتصال اینترنت برقرار نیست».
- [ ] بعد از خروج از حساب و قطع اینترنت، هیچ صفحهٔ شخصی نمایش داده نمی‌شود.
