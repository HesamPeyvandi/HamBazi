# تحویل فاز ۷ — تکمیل بریف، پاسخ در چت، رنگ هویتی، علاقه‌مندی، لیست انتظار، پشتیبانی، کارمند سالن

## ۱. چه چیزی ساخته شد
| بخش | خلاصه |
|---|---|
| چت: پاسخ به پیام | دکمهٔ «پاسخ» روی هر پیام، نوار نقل‌قول بالای ورودی (قابل لغو)، پرش به پیام اصلی با کلیک روی نقل‌قول. پاسخ فقط به پیام همان اتاق. پیام پنهان‌شده در نقل‌قول «پیام در دسترس نیست» نشان می‌دهد. |
| رنگ هویتی | برای نام و آواتارِ کاربر بدون عکس، رنگ ثابت از یک پالت ۱۰ رنگ بر پایهٔ هش شناسهٔ کاربر (همیشه یک رنگ برای یک نفر). |
| هیرو | گرادینت صفحهٔ اصلی سبک‌تر شد تا عکس بیشتر دیده شود (دسکتاپ و موبایل). |
| علاقه‌مندی | قلب روی کارت سالن (برای مهمان به ورود هدایت می‌کند)، صفحهٔ `/favorites`. |
| لیست انتظار | وقتی سانس پر است: «ورود به لیست انتظار» (همان شرایط پیوستن: لینک دعوت، بازهٔ مهارت، مهلت). با آزاد شدن جا، نفر(های) اول یک اعلان می‌گیرند. سقف ۲۰ نفر. |
| بازپرداخت مابه‌التفاوت | اگر کسی دیر لغو کند (بازپرداخت جزئی) و بازیکن دیگری جایش را بگیرد و پرداخت کند، بقیهٔ پول او (شبیه‌سازی‌شده) در ردیف جدا برمی‌گردد؛ یک‌بار و هرگز بیش از مبلغ پرداختی. |
| پشتیبانی | `/help` (سؤالات متداول + فرم پیام؛ ۳ پیام در ساعت، یک پیام باز برای هر موضوع) و `/admin/support`. |
| ادمین | `/admin/sessions`، `/admin/reviews` (پنهان/بازگرداندن نظر با بازمحاسبهٔ امتیاز سالن و اعلان به نویسنده، audit-log). |
| مالک | `/owner/sessions` (سانس‌های باز + تعداد تأییدشده/در انتظار پرداخت)، بخش «کارمندان سالن» در صفحهٔ سالن. |
| کارمند سالن | مالک با شمارهٔ موبایل (کاربر باید قبلاً ثبت‌نام کرده باشد) کارمند اضافه/حذف می‌کند. کارمند: سانس‌ها، رزروها، حضور و غیاب. فقط مالک: ویرایش اطلاعات، عکس، ارسال برای تأیید، مدیریت کارمندان. سالنِ غیرمرتبط ← ۴۰۴. |

## ۲. مهاجرت‌ها
`0008_phase7_completion` و `0009_chat_reply` — جدید. اجرا: `npm run db:migrate` (روی Neon هم همین دستور با `DATABASE_URL`).
متغیر محیطی جدید: **ندارد**.

## ۳. اجرا و تست محلی
```
npm install
npm run db:migrate && npm run db:seed
npm run dev          # یا: npm run build && npm start
npm test             # Vitest (نیاز به Postgres؛ README)
E2E_DB_URL=<url> node tests/e2e/phase7.mjs   # سرور production باید روشن باشد
```
نتیجهٔ واقعی این تحویل: Vitest ‏۱۸۸/۱۸۸؛ E2E فازهای ۱ تا ۷: ۷۲، ۶۲، ۴۷، ۶۶، ۳۹، ۲۸، ۲۳ بررسی، همه پاس؛ `tsc`، `eslint` و `next build` بدون خطا.

## ۴. محدودیت‌ها و آنچه تست نشده
- لیست انتظار و بازپرداخت مابه‌التفاوت فقط با تست واحد روی دیتابیس واقعی پوشش داده شده‌اند، **نه** با تست مرورگر.
- تست مرورگر نظر پنهان‌سازی را فقط تا باز شدن صفحهٔ `/admin/reviews` می‌رود؛ منطق در Vitest تست شده است.
- افزودن کارمند فقط برای کسی ممکن است که قبلاً ثبت‌نام کرده؛ دعوت از کاربر ثبت‌نام‌نشده وجود ندارد. کارمند نقش سراسری `venue_manager` می‌گیرد (خروج او از سالن این نقش را برنمی‌گرداند).
- پرداخت همچنان شبیه‌سازی‌شده است (درگاه واقعی طبق تصمیم شما حذف شد). پیامک OTP هنوز provider آزمایشی است.
- PWA/آفلاین و سخت‌سازی نهایی (فاز ۸ و ۹) انجام نشده.

## ۵. چک‌لیست پذیرش
- [ ] در چت روی «پاسخ» بزنید، پیام بفرستید؛ نقل‌قول دیده می‌شود و با کلیک به پیام اصلی می‌پرید.
- [ ] دو کاربر بدون عکس رنگ‌های متفاوت و ثابت دارند.
- [ ] هیرو: عکس بیشتر از قبل دیده می‌شود (موبایل و دسکتاپ).
- [ ] قلب سالن → `/favorites`.
- [ ] سانس پر → لیست انتظار؛ پس از لغو یک نفر، اعلان می‌آید.
- [ ] `/help` پیام می‌فرستد؛ ادمین در `/admin/support` می‌بیند و می‌بندد.
- [ ] مالک: `/owner/sessions`؛ افزودن کارمند؛ کارمند فرم ویرایش سالن را نمی‌بیند؛ پس از حذف، صفحهٔ سالن ۴۰۴ می‌شود.
