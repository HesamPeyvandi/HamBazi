# پرسش‌های مسدودکننده (یک‌جا)

1. **ورود:** تصویر ورود/ثبت‌نام رمز عبور و «ورود با Google» دارد؛ بریف فقط OTP. آیا تأیید می‌کنید که **فقط OTP** (بدون رمز و Google) پیاده شود و فرم ثبت‌نام = نام + موبایل + کد معرف اختیاری + قوانین؟
2. **تیم/دامنه:** آیا دامنه‌ای (مثلاً hambazi.ir) دارید یا فعلاً از آدرس `*.vercel.app`/آزمایشی استفاده کنیم؟
3. **حساب‌های سرویس:** آیا ایجاد حساب در Neon (یا Supabase) و ذخیره‌ساز فایل برایتان از ایران امکان‌پذیر است؟ (اگر نه، فاز ۱ را با Postgres محلی/Docker می‌سازم و انتخاب هاست را بعد از تست دسترسی نهایی می‌کنیم.)
4. **دارایی‌های تصویری:** برای seed (عکس سالن‌ها، لوگو) آیا اجازه می‌دهید از خود عکس‌های مرجع بریده و به‌عنوان عکس **نمونه‌ٔ دمو** استفاده کنم، یا فایل‌های جداگانه/لوگوی اصلی می‌فرستید؟ (پیش‌فرض: بله برای دمو، با برچسب «نمونه»؛ لوگو را از روی مرجع بازسازی می‌کنم.)

برای بقیه موارد فرض‌های مستند بالا استفاده می‌شود.

# تست دسترسی از ایران — مراحل دقیق

هدف: بفهمیم صفحه‌ای که روی Vercel میزبانی می‌شود از شبکهٔ **ایران** (بدون VPN) باز می‌شود یا نه.

1. در [vercel.com](https://vercel.com) حساب بسازید (ممکن است برای خودِ ثبت‌نام/ورود به داشبورد به VPN نیاز باشد؛ این را هم یادداشت کنید).
2. روش سریع بدون ابزار: پروژهٔ جدید ← **Import** یا آپلود پوشهٔ `iran-reachability-test/` (فقط یک فایل `index.html` است؛ Framework Preset: **Other**، Build Command خالی، Output Directory `./`). یا با CLI: `npm i -g vercel && cd iran-reachability-test && vercel --prod`.
3. آدرس `https://<نام>.vercel.app` را بگیرید.
4. **بدون VPN**، با دو شبکهٔ مختلف (مثلاً اینترنت ثابت/ADSL و موبایل: همراه اول، ایرانسل) آدرس را باز کنید.
5. اگر باز نشد، خطا را بنویسید (timeout / ERR_CONNECTION_RESET / صفحهٔ فیلترینگ / HTTP کد).
6. تست جانبی: همین صفحه را روی یک سرویس دیگر (مثلاً Cloudflare Pages یا GitHub Pages) هم بگذارید و مقایسه کنید.
7. نتیجه را برایم بنویسید: «باز شد/نشد» برای هر شبکه + پیام خطا. **تا آن زمان من نتیجه را فرض نمی‌کنم.**

نکته: فایل با یک هاست ایرانی (لیارا/آروان) هم قابل آزمایش است تا گزینهٔ جایگزین آماده باشد.
